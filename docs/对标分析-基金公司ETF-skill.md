# 对标分析：基金公司 ETF Skill 的能力矩阵 vs 我们的金融服务

> **背景**：用户转发《ETF skill 突然火了》一文（中国基金报，2026-11-09）。
> 易方达 / 南方 / 华泰柏瑞 / 华宝等基金公司把 ETF 数据能力封装成 AI 可调用的 skill。
> 本文回答三个问题：**它们的 skill 怎么分析标的？需要/提供哪些指标？我们几个金融服务要不要补齐？**

## 一、它们提供什么（按文章公开信息整理）

### 华泰柏瑞 ETF_SKILL —— 六类功能

| 功能块 | 指标 / 信息 |
|--------|-------------|
| 产品资料与风险收益特征 | 净值、规模、费率、成立日期、跟踪误差、风险等级 |
| 资金与两融 | **ETF 融资融券余额**、资金净流入/流出 |
| 财务与估值 | 基金财务指标、**指数估值** |
| 指数资料与行情 | 指数行情、成份股、权重 |
| 基金经理 | **基金经理标签和观点**（特色） |
| 申赎与盈利预测 | 申赎清单、**基金指数盈利预测**（特色） |

规划中：指数多周期行情、港股指数行情、指数融资融券、指数资金流向、基金经理画像、基金经理持股集中度、概念持仓分布。

### 易方达 指数直通车 Skill —— 47 个数据能力

- 覆盖**指数 / 场内 ETF / 场外联接基金 / 股票**四类对象的数据关联
- 特色：**指数估值分位**、**历史股息率**、ETF 实时行情、场外联接基金财务指标
- 分发：GitHub / 腾讯 SkillHub / ClawHub + WorkBuddy / 千问 / 腾讯 ima

### 南方 ETFirst Skill —— 口径纪律 + 分层用户

- 指标：实时行情（秒级）、历史业绩、资金流向、估值水平、成份股构成、**行业分布**
- 三条产品逻辑值得抄：
  1. **口径可控**：数据与自家小程序同源，回答**逐项标注数据日期**、区分数据频率（秒级行情 / 日频估值 / 季度披露）
  2. **结构化输出、报错明文化**：让 AI 能理解并自主纠正、重试
  3. **平台无关**：一套产出全生态通用，新平台一次验证即接入
- 下一版：**策略 skill**（动态哑铃 / 智慧网格 / 时点动量 / 风格轮动），支持多轮对话明确目标与风险偏好，策略收藏后 AI 持续监测、**主动推送信号与跟踪小结**

### 华夏 / 嘉实（筹备中）

- 华夏：ETF 观势知心 / 热点解读 / 收盘解读（盘前-盘中-收盘全环节）；筹备**指数对比器、持仓 AI 诊断、指数回报提升器、历史回测器**
- 嘉实：指数前十大权重、估值、基本面；ETF 价格走势、重仓成份股、业绩表现；**监控任务（指标变化自动提醒）**

## 二、它们怎么分析标的（方法论）

从功能矩阵反推，四家的分析套路是同一个骨架：

```
 选标的（筛选/对比）
   ↓
 看价格（实时行情 + 历史业绩）
   ↓
 看资金（资金流向 / 两融 / 申赎）
   ↓
 看估值（指数估值 / 估值分位 / 股息率）
   ↓
 看构成（成份股权重 / 行业分布 / 持仓集中度）
   ↓
 看人（基金经理标签 / 观点 / 持股集中度）
   ↓
 看预期（盈利预测 / 监控提醒）
```

三个共性设计原则：

1. **对标的不做"结论"，只做"画像"** —— 数据一次取齐，判断留给用户/Agent
2. **每个数字都带口径和日期** —— 秒级/日频/季度分开标注，防止 AI 混用
3. **监控 + 主动推送** —— 从"人找信息"走向"信息找人"（嘉实监控任务、南方策略订阅）

## 四、差距清单（按价值排序）

| # | 补齐项 | 服务于哪层 | 价值 | 工作量 |
|---|--------|-----------|------|--------|
| 1 | **指数/ETF 基础画像**：净值、规模、费率、跟踪误差、成份股权重前 10、行业分布 | 采集线 + 分析线 | 高——四家 skill 的共同底座 | 中 |
| 2 | **指数估值分位 + 历史股息率** | 采集线 | 高——易方达的核心卖点；长期预测的重要因子 | 中 |
| 3 | **ETF 资金流向 + 两融余额** | 采集线 | 高——短期预测的直接输入 | 中 |
| 4 | **个股↔指数关联**（某股属于哪些指数/ETF，权重多少） | 采集线 + 分析线 | 高——打通"持仓标的→所属指数→行业位置"链路 | 中 |
| 5 | **预测因子结构化**：把估值分位/股息/资金流做成 predictions.factor_snapshot 的标准字段 | 预测服务 | 高——让复盘能归因到具体因子 | 小 |
| 6 | **监控任务通用化**：任意指标（估值分位、资金流突变、权重变化）设置阈值→自动提醒 | 分析线 + App | 中高——嘉实已验证需求 | 中 |
| 7 | **对比器**：多标的横向对比（同类 ETF 溢价、费率、跟踪误差） | App / Web | 中 | 中 |
| 8 | **回测器** | 分析线 | 中——华夏在筹备，说明需求真实 | 大 |
| 9 | **基金经理画像** | 采集线 | 中低——依赖外部数据源 | 中 |
| 10 | **口径纪律**：所有接口输出带 `as_of` + 频率标注 | 全部 | 高且便宜——南方的核心经验，防 AI 混用口径 | 小 |

## 五、建议补齐顺序（三期）

### 第一期（口径与画像底座，1-2 周）
1. **口径纪律**：8084 全部 GET 输出补 `as_of` / `frequency` 字段；预测服务输出同样补
2. **个股↔指数关联表**：从公开指数编制方案/akshare 拉成份股，入 `index_constituents` 表
3. **预测因子结构化**：predictions.factor_snapshot 固定为 `{price, rsi, macd, fund_flow, valuation_percentile, dividend_yield, industry_rank}`

### 第二期（ETF/指数专项，2-3 周）
4. **ETF 基础画像接口**（规模/费率/跟踪误差/折溢价）
5. **指数估值分位 + 股息率**（基于已有日K + 成份股财报）
6. **App 指数/ETF 详情页**：画像卡 + 估值分位图 + 资金流

### 第三期（监控与策略，2 周+）
7. **监控任务通用化**：watch_tasks 表 + 阈值引擎 + 飞书/App 推送
8. **策略 skill 化**：把 dsa-mcp 15 个 YAML 策略包装成可对话调用的形式
9. **回测器**（可选，工作量大，视需求）

## 六、不建议抄的部分

| 它们的做法 | 为什么不抄 |
|-----------|-----------|
| 上架第三方技能市场（WorkBuddy/SkillHub） | 我们的服务是自用 + 自有 App，MCP（stdio/HTTP）已是标准接口，无需再封装一层市场协议 |
| 盈利预测对外发布 | 合规成本高；我们的预测定位是"研究参考"而非投顾服务 |
| 基金经理观点/标签 | 依赖人工运营，数据源不在我们手里 |

---

## 结论

四家 skill 的核心不是"新算法"，而是**数据完整性 + 口径纪律 + 主动推送**三件事。我们采集线的数据面已经覆盖它们功能的 70%，真正缺的是 **ETF/指数专项数据、估值分位、个股↔指数关联、监控任务通用化**这四块，以及把"所有输出带口径与日期"变成纪律。按上面三期补齐后，我们的 8084 + 预测服务 + App 组合在数据能力上不弱于任何一家的 skill，且多了它们没有的自闭环复盘层。
